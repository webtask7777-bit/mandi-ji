# SahiBhav editorial publishing

This release adds discovery and publishing controls, not hundreds of autogenerated articles. The catalogue audit reviewed on 22 October 2026 records all 388 commodity IDs. 275 IDs belong to 165 curated editorial topics; 15 animal/aquatic goods, 27 mixed or unspecified goods and 71 identities or dedicated editorial topics awaiting review remain outside crop-specific article matching. See `crop-topic-coverage.json` for every disposition and its reason.

## Content sources and publishing

`content/editorial/*.json` holds the maintained guide files. `server/db/data/blog-posts.json` is the runtime/build collection. Preserve the existing `id`, slug and original `publishedAt` when editing. Change `updatedAt` only for a real content or metadata change; do not refresh dates to imply a new weather event. The publisher must actually read a source before changing its `accessedAt` date.

After an intentional source-file edit:

```sh
npm run sync:editorial
npm run check:editorial
npm run build
npm test
```

Sync upserts by stable ID, checks slug collisions and preserves unrelated CMS entries. It does not fetch or generate new facts. Build fails for invalid publication metadata, missing cover files, broken internal article references, duplicate bodies, invalid dates or source/runtime divergence. Review the diff before deployment.

The current JSON store writes repository files. Local admin saves require a writable filesystem; Vercel serverless files are not a durable content database. Production publication in this project therefore uses committed source files and a new deployment. Do not describe the current admin form as a persistent hosted CMS. A future durable database must also refresh prerendered pages and sitemap when content changes.

## Required editorial decisions

- `cropTopics`: explicit IDs from `shared/cropTopics.js`. Source commodity IDs and their prices stay separate. A family-level article must identify which form/stage it covers. Do not apply raw-crop treatment to processed products just because their family matches.
- `stateIds`: an empty list means general applicability; a specific list limits discovery to those states. Always give a readable `regionLabel`. A local example does not make a guide universal.
- `sources`: relevant primary references, actual HTTPS URLs, descriptive titles and actual source-access dates. Separate dated examples from current advisories.
- `coverImage`, `coverAlt`, `coverCaption`: existing local asset, meaningful accessible description and honest illustration disclosure. Reuse the same crop visual for translations when appropriate; do not present generated illustrations as field evidence.
- `language`: `hi`, `mr` or `gu`; `translationGroup` is shared only by genuinely equivalent translations. Each published language version has its own canonical and reciprocal alternates, including itself. No empty language pages.
- `editorialNote`: describe AI-assisted preparation/translation honestly. No invented expert, reviewer or field visit. Actual editorial attribution remains the SahiBhav organization.
- `weatherRelevant`: exposes the IMD district advisory links. The links do not embed a live forecast. Ask readers to check district, issue time, validity and crop stage.
- `priceLinks`: explicit valid commodity/state price routes. Never label historical/monthly records as today's prices. Use the delivery and net-sale calculators with the reader's own verified inputs.

API filtering happens before pagination. Crop matches use the curated exact-ID lookup; related articles are resolved by explicit slug without a first-50 limit. Search/filter URLs are useful navigation and stay out of the index. Only complete published articles create indexable routes.

## Expansion sequence

Start with substantive guides for paddy, wheat, maize, gram, mustard, soybean, cotton, arhar, moong, urad, masoor, bajra, jowar, sugarcane, groundnut, onion, potato, tomato, garlic and chilli. Existing guides should be expanded when the search intent is the same; create a separate article only for a materially different question with enough crop-specific evidence.

For each topic, prioritize regional suitability and sowing preparation, seasonal decisions, harvest/storage, and sale/transport decisions. Link every useful guide to precise price pages and calculators. Do not duplicate a general guide across dozens of state names; a regional page needs region-specific facts and sources. Unknown labels such as Marget or Delha must stay out of species-specific agronomy until identified.

The first multilingual example is the tomato sale/transport guide in Hindi, Marathi and Gujarati. Continue language expansion with source-checked content and native-language review. Language availability must represent an actual complete article, not just a translated title.

Use Search Console impressions, clicks, indexing and queries to select the next crop/state/language. No search-volume or traffic forecast is supplied by this implementation. Check performance against a real baseline after deployment.
